# Соглашения API

Обязательны для новых API вместе с [правилами команды](TEAM_WORKFLOW.md). Рабочий образец: `src/modules/notes/`, его `openapi.yaml`, `tests/notes.test.ts` и `scripts/notes-smoke.ts`.

## Три уровня требований

- Этот файл задаёт общие правила, а не перечень реализованных endpoints.
- `src/modules/<module>/openapi.yaml` — точный контракт конкретного модуля: методы, пути, входы, ответы, заголовки, ошибки и примеры. Меняйте его в том же PR, что и поведение; не оставляйте расходящиеся копии схем и документации.
- Issue задаёт цель, границы и проверяемые критерии приёмки. Критерии не заменяют OpenAPI. Изменение согласованного контракта сначала согласуйте с captain в Issue.

## Пути, данные и HTTP

- Новые JSON endpoints находятся только под `/api`. Имена ресурсов — существительные во множественном числе, сегменты — `kebab-case`; поля JSON — `camelCase`. Идентификатор ресурса идёт в path, фильтры — в явно описанных query-параметрах. Не вводите действия в URL вместо HTTP-методов без согласования.
- GET читает без изменения данных: `200` с представлением, `404` при отсутствии. POST создаёт: `201` с созданным представлением и `Location`. DELETE удаляет: `204` без тела, `404` при отсутствии. Другие методы и статусы вводятся только явным контрактом модуля; наличие соглашения не означает наличие endpoint.
- Возвращайте объект ресурса напрямую. Не вводите общую обёртку `success`, `data` или `error`. Даты — строки ISO 8601, UUID — строки.
- Для новых списков используйте `{ "items": [...] }`. Если задача явно вводит курсорную пагинацию, добавляйте `nextCursor`: строку для следующей страницы либо `null` в конце, например `{ "items": [...], "nextCursor": null }`. Параметры, ограничения, стабильный порядок и содержимое элементов задаются OpenAPI модуля. Список, update и пагинация в Notes не реализованы: соглашение не добавляет endpoints автоматически.

## Границы и ошибки

- На границе валидируйте body, path и query схемами Zod. Объекты строгие: неизвестные поля отклоняются. Используйте только успешный результат разбора, типы выводите через `z.infer`. Не подменяйте проверку приведением типа и не преобразуйте некорректный ввод молча.
- Каждый endpoint явно разрешает query-параметры либо запрещает их. JSON-body требует `Content-Type: application/json`; неподдерживаемый media type — `415`. Общий JSON parser под `/api` ограничен `16kb`: некорректный JSON — `400`, превышение лимита — `413`, неподдерживаемая кодировка — `415`.
- Ошибки API формирует только общий обработчик `src/http/problem.ts` в формате RFC 9457 с `Content-Type: application/problem+json`: `{ "type": "about:blank", "title": "Bad Request", "status": 400, "detail": "…", "instance": "/api/notes" }`. `title` — каноническое HTTP-название статуса; `instance` — путь запроса без query.
- Используйте общий `ApiError` для ожидаемых `400` (невалидный ввод), `404` (ресурс/маршрут не найден), `409` (описанный конфликт) и `415` (неподдерживаемый формат). Не добавляйте локальные форматы ошибок. Неизвестная ошибка — обезличенный `500`; stack trace, SQL, сообщения драйвера и секреты не попадают в API ни в каком режиме. Ошибки async-обработчиков передавайте через механизм Express 5, не скрывайте исключения fallback-ответами.

## Сборка приложения и legacy

- Модуль экспортирует фабрику router с внедрённым `Database`. Не создавайте PrismaClient на запрос. Captain явно подключает router в `createApp(db)`; автопоиска middleware нет. Модуль не открывает порт.
- Существующие GET `/`, `/users`, статические файлы и HTML-ошибки вне `/api` остаются legacy-контрактом. Не переводите их на JSON и не меняйте их parser/ошибки попутно. Неизвестный путь под `/api` возвращает Problem `404`, а не HTML.

## Проверяемый образец Notes

- POST `/api/notes`: только JSON `{ "content": "…" }`, без query и неизвестных полей. После trim длина `content` — 1–2000 единиц UTF-16 (длина строки JavaScript). Ответ `201`: `{ "id": "UUID", "content": "…", "createdAt": "ISO8601" }`, `Location: /api/notes/{id}`.
- GET `/api/notes/{id}`: UUID проверяется до обращения к БД; `400` для неверного UUID, `200` для существующей заметки, `404` для отсутствующей.
- DELETE того же пути: такая же проверка UUID; `204` с пустым телом либо `404`.
- Это неаутентифицированный учебный пример: не храните чувствительные данные. Автотесты HTTP-границ используют настоящее приложение без внешней БД и без подмены БД. Создание, чтение, отсутствие и удаление проверяет smoke с настоящим PostgreSQL; не выдавайте mocks или чтение исходников за эту проверку.
